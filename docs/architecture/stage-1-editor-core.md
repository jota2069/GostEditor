# Этап 1: укрепление редакторского ядра

## Статус

Этап реализован как совместимый переходный слой поверх `.gost v2`.
Формат архива и `document.json` не изменены. Существующие документы по-прежнему
загружаются в `GostDocument`, а новое структурированное дерево доступно через
`LegacyDocumentAdapter` и `LegacyDocumentEditingBridge`.

## 1. Структурированная модель

Основные узлы:

- `DocumentRoot`;
- `DocumentSection`;
- `ParagraphBlock`, `FigureBlock`, `CodeBlock`, `TableBlock`,
  `PageBreakBlock`;
- `TextInline`, `LinkInline`, `LineBreakInline`;
- `DocumentResourceCatalog`.

Все узлы получают `DocumentNodeId`. Идентификатор сохраняется в течение жизни
модельной сессии и используется операциями, выделением и layout invalidation.
Он намеренно не записывается в `.gost v2`: постоянное хранение ID потребует
отдельной спецификации v3 и миграции.

## 2. Граница совместимости v2

`LegacyDocumentAdapter` выполняет двустороннее преобразование. Если новая
модель содержит данные, которые v2 не способен сохранить без потерь
(несколько секций, колонтитулы, полноценные таблицы), обратное преобразование
завершается `NotSupportedException`, а не тихой потерей содержимого.

`DocumentEditor.CreateStructuredEditingSession()` создаёт структурированную
сессию из текущего документа. `ApplyStructuredDocument()` применяет результат
обратно через проверяемую границу совместимости.

## 3. Редактирование и история

Новая модель использует обратимые операции:

- вставка и удаление текста;
- замена диапазона, включая несколько абзацев;
- разделение и объединение абзацев;
- изменение текстового и абзацного форматирования;
- добавление и удаление блоков;
- `EditTransaction` для единой записи undo/redo.

Активный legacy-редактор больше не хранит полный снимок всего документа для
обычных пользовательских действий. `DocumentMutationCommand` сохраняет только
затронутый диапазон абзацев и, только для операций с изображениями, каталог
изображений. Неизменённые абзацы не заменяются при undo/redo.

`DocumentEditor` разделён на partial-файлы по ответственности:

- `DocumentEditor.TextEditing.cs`;
- `DocumentEditor.Formatting.cs`;
- `DocumentEditor.Navigation.cs`;
- `DocumentEditor.Blocks.cs`;
- `DocumentEditor.Images.cs`.

## 4. Инкрементальный layout

`PageLayoutManager` кэширует `TextLayout` каждого абзаца. Ключ учитывает текст,
форматирование, параметры страницы, гарнитуру и параметры рисунка.
`DocumentChanged` сообщает минимальный индекс изменения и его тип.
`RenderController` передаёт invalidation в layout manager.

Поведение:

- изменение каретки или выделения повторно использует все измеренные абзацы;
- изменение текста/метрик удаляет кэш только от затронутого абзаца до конца;
- структурные изменения также инвалидируют только суффикс;
- смена параметров страницы или гарнитуры сбрасывает весь кэш;
- `LayoutBuildStatistics` показывает hits, misses, количество страниц и время.

Пагинация и размещение каретки пересобираются, но дорогое формирование
`TextLayout` повторно не выполняется для неизменённого префикса. Это безопасная
основа для следующего шага — page-snapshot reuse и виртуализации страниц.

## 5. Инварианты

- `.gost v2` не изменён;
- старые v0/v1 продолжают мигрировать через существующий pipeline;
- изображения остаются канонически в `GostDocument.Images`;
- операции не должны тихо терять неподдерживаемые узлы;
- один пользовательский составной шаг создаёт одну запись истории;
- undo/redo инвалидирует тот же диапазон, что исходная операция;
- layout-кэш не является источником данных и может быть сброшен в любой момент.

## 6. Проверки

Добавлены тесты для:

- стабильных ID;
- round-trip legacy ↔ structured;
- операций и транзакций;
- многоабзацного удаления и форматирования;
- split/merge;
- локального undo/redo без замены неизменённых абзацев;
- событий изменения;
- layout cache hit/miss и локальной invalidation.

Обязательная проверка после переноса файлов:

```bash
dotnet build GostEditor.sln --no-restore
```

После успешной сборки выполняются выборочные тесты и затем полный набор.
